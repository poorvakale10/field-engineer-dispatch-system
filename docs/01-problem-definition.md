# Task 1 — Problem Definition and Scope

## Problem
Field service teams often manage requests, engineer assignments and status updates through spreadsheets, calls or disconnected tools. DispatchFlow centralizes these records and makes dispatch status visible.

## Users
Dispatcher, Field Engineer, Admin/Supervisor.

## Stakeholders
Operations manager, dispatchers, engineers, customer/service desk, IT/DevOps team and evaluator.

## Pain points
Manual assignment, repeated follow-up, poor visibility, inconsistent status updates, difficult searching and no automated testing/deployment.

## Objectives
Centralize requests; reduce manual work; provide status visibility; automate build/test/deployment; validate workflows with Selenium.

## Constraints
Academic MVP, local infrastructure, demo data, no production integrations and simplified authentication.

## Success criteria
Create/view/update/search works; status workflow works; dashboard counts are visible; Maven build succeeds; Selenium suite runs; Jenkins builds/tests; Docker container runs; Ansible can be rerun safely.

## Approved 15-task MVP
1 Login  2 Role concept  3 Create request  4 View requests  5 Search  6 Update  7 Assign engineer  8 Change status  9 Engineer view  10 Engineer update  11 Priority  12 Dashboard totals  13 Status summary  14 Validation  15 Selenium automation
